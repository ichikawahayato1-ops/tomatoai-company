# TomatoAI Company

Ownerとして小さなAI会社を眺めるオフィスMVP。採用版は、TOMAのイラスト素材を使ったゆっくりした歩行・着席・仕事の受け渡しと、作業内容・短い会話の吹き出しです。

## 起動

```sh
cd /workspace/tomatoai-company
npm ci
npm start
```

ブラウザでポート3000を開いてください。社員をクリックするとFOCUS VIEWへ移動し、Escapeまたは「Officeを見る」で戻ります。納品BOXをクリックすると成果物一覧を開きます。スマートフォン、キーボード操作、動きを減らす設定に対応しています。

初期状態は仕事の依頼なしの動作実験です。社員は歩行・PC作業・読書・休憩を続けます。「新しい仕事を依頼」から LYCO → SOL → POMO → RUBYの修正と再評価 → CEO → 納品BOXの仕事デモを開始できます。実際のAI処理はまだ未接続です。

キャラクターはTOMA設定画を基に生成した透過素材を使用します。正面・横・後ろの向き、手足のアニメーション、着席専用素材、資料の受け渡しを組み合わせています。吹き出しは作業や移動、受け渡しに連動し、近くのキャラや他の吹き出しを避けて表示します。眠そうな半目・目を閉じた睡眠の専用素材に切り替わります。ひらめきの電球、修正相談の「？」と汗、完成時のハートとキラキラも状態に連動します。顔が見える場面では、通常・集中・ひらめき・困り顔・にっこりの表情素材を切り替えます。歩行や後ろ向きのPC作業の向きは保ちます。まばたきは未実装です。

## Agent接続

`state.js`: Agent状態とイベント保存、`characterState`: 行動への変換、`app.js`: SVG描画と移動、デモ制御。バックエンドは未接続です。実際のイベントを受信するアダプターから次を呼び出してください。最初の有効なイベントでデモは停止します。

```js
window.tomatoOffice.dispatch({
  agentId: 'research', status: 'handoff', task: '投稿の調査',
  progress: 100, from: 'Owner', to: 'creator', destination: [300, 439]
});
window.tomatoOffice.dispatch({type: 'delivery', id: 'task-142', title: '投稿デザイン'});
```

状態: idle, researching, analyzing, creating, reviewing, handoff, rejected, completed, resting, sleeping, walking。移動先を省略すると自席に戻ります。納品イベントはIDで重複防止。タスクの文章はHTMLとして描画しません。正式素材は `app.js` のキャラクター描画のみを差し替え、Agent処理を維持できます。社員定義は `state.js` に集約しています。納品・状態はメモリ内のみで、再読込するとデモがリセットされます。

## 検証

```sh
npm test
```

状態変換、イベント検証、進捗上限、納品重複防止を検査します。外部フォントが利用できない場合はOSフォントで表示します。

現在の表示は `app.js` と `style.css` のスプライト描画です。検討中の `character-3d.js` は読み込みません。

「表情・エフェクトを見る ♪」で、CEOが休憩スペースへ移動し、眠気→睡眠→集中→ひらめき→困る→完成を7秒ずつ見られます。通常の動作実験でも休憩の後に眠気・睡眠が入ります。`dozing` と `sleeping` はAgentイベントでも指定できます。

## TOMAとの一対一画面

オフィスのCEOまたは「TOMAに相談する ♡」から専用の相談室を開きます。机越しのTOMAを大きく表示し、ゆっくりした呼吸・まばたきと、聞く／考える／笑顔で返事する素材を切り替えます。画面の戻るボタンまたはEscapeでオフィスへ戻ります。スマートフォンでは相談欄がキャラの下に並びます。

`ceo-view.js` に画面・会話のデモを分離しています。送信内容に合わせた定型の案内と、OfficeStoreの現在の社員状態・納品件数を表示します。実際のAIとの会話・音声・会話履歴の永続保存は未接続です。入力文章はtextContentで表示します。

一対一画面の背景は `assets/ceo-office.png`。ガラスの間仕切り越しの仕事場、書類棚、ホワイトボード、窓の外のビルを描いたオフィス背景を使い、TOMAと手前の机の小物を重ねています。

相談室の「表情を見てみる ♡」から、にっこり・ワクワク・真剣・困り顔・照れ顔・眠そうの6表情を試せます。会話デモでは入力に応じて表情を選び、返事の後は通常の聞く表情に戻ります。表情素材は `assets/toma-ceo-emotions.png` にまとめています。

表情は追加の6種類（安心・びっくり・きょとん・くすくす・ウインク・まかせて）を含む12種類です。`portrait-motion.js` で約340msのクロスフェードを行い、連打時は最後の指定へ切り替えます。呼吸を継続しながら、うなずき・首の傾きを重ねます。動きを減らす設定では切り替えと仕草のアニメーションを止めます。顔の部位を連続変形する3Dリグではなく、表情イラストのブレンドです。

### 会社の仕事ノート
相談画面・オフィス画面の下で依頼を登録できます。TOMA → LYCO → SOL → POMO → RUBY → TOMA の順に、手動の「デモ確認」ボタンで進行します。レビュー時には制作担当へ差し戻せます。担当状態と引き継ぎはオフィスの表示に反映されます。
依頼・進行・履歴・依頼整理シートをブラウザのlocalStorageに保存し、納品後にはMarkdownでダウンロードできます。成果物はテンプレートです。実際のAI調査・制作・審査は未接続です。保存は利用しているブラウザに限られ、履歴を削除すると失われます。
単体HTMLの再生成は `python3 scripts/build-standalone.py`。出力は親フォルダの `TOMA-preview.html` です。

### Webアプリ版
`npm start` で、画面とAPIを同じサーバーから提供します。TOMAの相談室が初期画面です。依頼と進行履歴はSQLiteに保存し、別のブラウザでも同じ依頼を表示します。約5秒ごとに最新状態を読み込みます。ネットワーク障害時は別のローカル保存へ切り替えず、エラーと再読み込みを表示します。既存の単体HTMLの依頼は自動移行されません。

サーバーの検証: `npm run test:server`。公開用設定はDEPLOY.md、render.yaml、Dockerfileを参照してください。Renderのアカウント接続とリポジトリ登録は別途必要で、現時点では未公開です。サーバー版の文章・企画のAI処理はAI-WORKFLOW.mdを参照してください。実通信は未検証です。

### SEEDの改善ノート
投稿名・記録日・リーチ・保存・いいね・フォロー増加を手入力し、気づきと次に試す改善を保存する。数値が未確認なら空欄、保存率はリーチと保存数がある場合のみ計算する。改善案／採用・検証待ち／結果確認済みを人が記録し、結果確認済みには比較結果のメモが必要。「次の企画に使う」はTOMAの入力欄へメモを渡すだけで、登録・制作・公開を実行しない。JSONバックアップが可能。
保存先はこのブラウザのlocalStorageで、GitHub PagesとMac版や別ブラウザとの自動同期、Instagram指標の自動取得、AI自体の学習は未接続。保存失敗は入力を残して通知し、破損データは上書きしない。
